# Q3Protocol

## PQXDH

### PQXDH Parameter Decisions
PQXDH requires several paremeters to be selected before implementation. The text for each of these parameters is taken directly from the [Signal's documents](https://signal.org/docs/specifications/pqxdh/pqxdh.pdf "PQXDH Documentation").\
The following parameters are listed as 
1. *parameter* = chosen parameter
2. "Description from documentation"
3. Our reasoning for selecting that parameter
4. Additional Info
<br><br>

#### *curve*
*curve* = curve25519\
"A Montgomery curve for which XEdDSA [1] is specified at present this is one of curve 25519 or curve448"

We did not implement XEdDSA in our project. Instead we split the identity key into 2 seperate X25519 and Ed25519 keys.
<br><br>

#### *hash*
*hash* = SHA-512
"A 256 or 512-bit hash function (e.g. SHA-256 or SHA-512)"
<br><br>

#### *info*
*info* = "Q3Protocol"
"An ASCII string identifying the application with a minimum length of 8 bytes"
<br><br>

#### *pqkem*
*pqkem* = ML-KEM-1024
"A post-quantum key encapsulation mechanism that has IND-CCA post-quantum security (e.g. Crystals-Kyber-1024 [2])"
<br><br>

#### *aead*
*aead* = AES-256-GCM
"A scheme for authenticated encryption with associated data that has IND-CPA and INT-CTXT post-quantum security"
<br><br>

#### *EncodeEC*
*EncodeEC* = 
"A function that encodes a curve public key into a byte sequence"
<br><br>

#### *DecodeEC*
*DecodeEC* =
"A function that decodes a byte sequence into a curve public key and is the inverse of EncodeEC"
<br><br>

#### *EncodeKEM*
*EncodeKEM* = 
"A function that encodes a pqkem public key into a byte sequence"
<br><br>

#### *DecodeKEM*
*DecodeKEM* = 
"A function that decodes a byte sequence into a pqkem public key and is the inverse of EncodeKEM"
<br><br>

### PQXDH Parameter Additional Info

#### Encoding Functions
The PQXDH documentation requires that all encoding functions must be "pairwaise disjoint". This just means that they should have no overlap for encoded keys.


The recommended implementation of both encode formats is a byte of our choice followed by "the little-endian decoding of the u-coordinate" In our implementation we used the byte 0x0 for curve25519 and 0xff for ML_KEM-1024. For the rest of the encoding we used the key bytes generated by OpenSSL for each key.


The size of the EncodeEC byte sequence is 33 bytes (1 byte + 32 bytes).
<br>
The size of the EncodeKEM byte sequence is 1,569 bytes (1 bytes + 1568 bytes).
